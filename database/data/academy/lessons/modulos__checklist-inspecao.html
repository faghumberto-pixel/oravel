Toda vez que uma Ordem de Serviço é criada, o sistema monta sozinho o checklist de vistoria dela, copiando os itens do Grupo de Checklist do ativo mais os itens extras cadastrados no próprio ativo. Se há preventivas vencidas ou vencendo no mês, entram também como itens “PMP”.

📍 Modelo: Ativos → Gestão de Ativos → Grupos de Ativos · Preenchimento: Manutenção → Operação → Ordens de Serviço (aba Vistoria / Checklist)

O modelo e a cópia

1Modelo (template)Itens básicos do Grupo + itens extras do ativo.
2OS é criadaO sistema gera o checklist sozinho.
3Cópia na OSO técnico preenche o checklist real.

Os três status de cada item

StatusSignificado
ConformePonto de inspeção OK. Conta como concluído.
Não ConformePonto com problema. O item não conta como concluído.
Não AplicávelO item não se aplica a este atendimento. Conta como concluído.
📋 Sempre uma cópia

Editar o modelo do Grupo ou do ativo depois não muda checklists de OS que já existem — só vale para as novas.

Pelo celular: o Modo Campo

O técnico preenche o checklist na etapa 2 do Modo Campo (botão Modo Campo (Celular) na OS). Cada item tem três botões: ✓ Conforme, ✗ Não Conforme e N/A. Tocar no item abre observação e foto.

  • Não Conforme exige observação e foto. Sem as duas, o sistema recusa e avisa: “Itens ‘Não Conforme’ exigem observação e foto.”.
  • Para conforme e N/A, observação e foto são opcionais.
  • A barra de progresso conta só os itens concluídos (Conforme e N/A). Um item Não Conforme fica fora da conta.
⚠️ Existem outras telas parecidas

Há uma tela mais simples, “checklist digital” (só marca e desmarca cada item, sem os três status), que só abre digitando o endereço; nenhuma tela do sistema leva até ela. O fluxo para ensinar é o Modo Campo. E o cadastro genérico Checklists (Manutenção → Cadastros) é solto: só tem nome e descrição, sem ligação com ativo, grupo ou OS.

Itens PMP dentro da OS

Ao criar a OS, cada plano preventivo ativo do ativo que está vencido ou vence no mês vira um item do tipo PMP. Eles aparecem na aba PMP da OS (que só existe quando há itens assim), com o mesmo preenchimento: Conforme, Não Conforme ou N/A, observação e foto. A observação do plano vira a instrução do item.

O que o sistema não faz

  • Concluir a OS não exige checklist completo. A cobrança é da equipe.
  • Marcar um item como Não Conforme não abre avaria nem pendência sozinho. Para isso, registre uma Avaria (veja Avarias) ou uma Pendência na OS.
  • Os itens ficam travados no nome: o técnico preenche status, observação e foto, mas não renomeia o item na OS.
👤 Quem usa

O supervisor de manutenção cadastra os itens padrão (no Grupo e, se for específico, no ativo); o técnico preenche o checklist real dentro da OS, normalmente pelo celular.

Quando usar

  • Ao definir os pontos de inspeção de todo equipamento de um grupo (na tela do Grupo).
  • Ao acrescentar um ponto que só vale para uma máquina, como itens do manual do fabricante (na tela do ativo).
  • Ao preencher a vistoria de uma OS em andamento.
